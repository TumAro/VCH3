# Manyavar Daily Stock Move Recommender

An autonomous, rule-compliant inventory rebalancing engine and merchandiser approval dashboard built for Vedant Fashions (Manyavar).

The system analyzes daily sales velocity, inventory runway, and route lead times across 20 retail stores and 1 central warehouse (`WH-KOL`) to generate an optimal, ready-to-approve list of stock transfers that a merchandiser can review in under 10 minutes.

---

## 🚀 Quickstart

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. Launch Web Dashboard (One Command)
```bash
python run.py
```
Opens the web dashboard at `http://127.0.0.1:8000`.

### 3. Run Headless CLI Pipeline (Batch Export)
```bash
python run.py --cli
# or directly:
python -m src.cli --data-dir data/csv --output-dir .
```
Generates `moves.csv` and multi-tab `moves.xlsx` (*Moves*, *Findings*, *Rejected Moves*) in $< 3\text{ seconds}$.

## 🏛️ System Architecture

Built under **Spec-Driven Development (SDD)** adhering strictly to the **Repository Design Pattern** and **SOLID principles**:

```
 ┌─────────────────────────────────────────────────────────────┐
 │                    Presentation Layer                       │
 │    FastAPI Endpoints  │  CLI Runner  │  Vanilla Web Dashboard │
 └──────────────┬───────────────────────────────┬──────────────┘
                │                               │
 ┌──────────────▼───────────────────────────────▼──────────────┐
 │                      Service Layer                          │
 │  • VelocityService (Stockout-aware units/day)               │
 │  • PositionCoverService (Effective stock & cover days)      │
 │  • ProblemDetectionService (Stockouts, ageing, imbalances)  │
 │  • MoveGenerationService (WH->Store, Store->Store)          │
 │  • ConstraintValidationService (6 hard rules & cumulative)  │
 │  • ExplanationService (Deterministic template strings)      │
 └──────────────┬──────────────────────────────────────────────┘
                │ Depends on abstractions (DIP)
 ┌──────────────▼─────────────────────────────────────────────┐
 │               Domain & Repository Interfaces               │
 │  Domain Models: Store, Item, StockPosition, Move, Finding   │
 │  Interfaces: IStoreRepo, IItemRepo, IStockRepo, IRulesRepo │
 └──────────────┬─────────────────────────────────────────────┘
                │ Implemented by
 ┌──────────────▼─────────────────────────────────────────────┐
 │              Infrastructure / Data Layer                   │
 │  CSVRepositories (Type casting, text IDs, packaging drops) │
 │  DataIssueLogger (Quarantine ledger for untrusted rows)     │
 └────────────────────────────────────────────────────────────┘
```

For detailed specifications, sequence diagrams, and design rationales, refer to [docs/architecture.md](docs/architecture.md).

## 🛡️ Non-Negotiable Hard Constraints

Every move generated by the engine passes through centralized individual and cumulative validation:

1. **Minimum Display (Rule 1)**: The giving store must remain at or above its tier and category minimum display (`min_display.csv`). Safa, Mala, and Stole are aggregated under Accessories.
2. **Store Capacity (Rule 2)**: The receiving store's on-hand + in-transit + cumulative accepted moves must never exceed `stock_capacity_units`.
3. **Flagship Protection (Rule 3)**: Top-20 styles at S++ flagship stores (`flagship_protected.csv`) are 100% blocked from outbound moves across all sizes.
4. **In-Transit Deduplication (Rule 4)**: Never transfers stock to a store that already has that SKU in transit.
5. **Donor Safety (Rule 5)**: Store-to-store moves must leave the donor with $\ge 30\text{ days}$ of cover for that style.
6. **High-Value Sign-off (Rule 6)**: Any single move with value $> ₹1,00,000\text{ MRP}$ is visibly tagged with a human approval warning.
7. **Cumulative Batch Pass**: Replays all proposed moves together against a running simulated inventory ledger, trimming or dropping moves that breach limits cumulatively.

## 🧪 Automated Test Suite

Run the full suite of **153 automated tests** verifying every requirement, edge case, and rule:

```bash
python -m pytest tests -v
```

### Key Test Coverage:
- `tests/test_ingestion.py`: Verifies 20 stores, 382 non-packaging items, string ID formatting, and quarantine of negative stock and snapshot mismatches.
- `tests/test_velocity_cover.py`: Verifies stockout-aware velocity ($\frac{\text{sales}}{\text{days\_in\_stock}}$), `BLR-05` peer fallback mean, and problem detection.
- `tests/moves/`: 100 tests verifying Warehouse-to-Store and Store-to-Store move generation, edge cases, and the 6 hard rules.
- `tests/test_integration_pipeline.py`: End-to-end integration test suite proving **zero rule violations** on real data via the independent validator.

## 📊 Output Artifacts

Running the pipeline or clicking export in the dashboard produces:

1. **`moves.csv`**: Flat CSV containing ranked approved moves with dispatch dates, arrival dates, route days, and data-backed rationale.
2. **`moves.xlsx`**: Multi-tab formatted Excel workbook:
   - **Sheet 1: Moves**: Ranked move proposals with high-value sign-off highlights.
   - **Sheet 2: Findings**: Surfaced stockout risks, ageing fashion traps, and zero-sales classifications.
   - **Sheet 3: Rejected Moves**: Full audit trail of candidate moves blocked by the safety engine with the exact broken rule recorded.
